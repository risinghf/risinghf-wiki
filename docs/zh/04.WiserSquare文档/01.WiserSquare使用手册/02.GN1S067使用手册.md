# WiserSquare-GN1S067使用手册

GN1S067 是瑞兴恒方开发的一款针对畜牧业牛羊定位和数据监测的智能化 LoRaWAN 追踪器。产品具有定位精度高，通讯距离远，待机时间长的特点。

本手册说明GN1S067产品在 WiserSquare 演示平台上的使用方法。产品的硬件参数、LoRaWAN 远程配置、APP 操作与安装方式请参考本文档；
平台的账号登录与固件版本管理请参考[《WiserSquare 平台使用手册》](./01.WiserSquare平台使用手册.md)。

主页面侧边栏有设备列表、电子围栏,
主页面右上角具有中英文切换以及用户详情等功能按钮;
主页面会统计当前用户下设备数量,当前报警设备数量,当前报警设备列表;
点击当前设备列表可进入设备详情查询设备历史警报信息;

## 4 应用数据推送

### 4.1 功能说明

设备上报的数据经平台解析、入库后，平台可以实时以 `HTTP POST` 的方式把本次上报的数据推送到用户自己的应用服务器，用于对接第三方的牲畜管理、地图展示等业务系统。

::: tip

1.2 节的「iotsquare-应用填写推送地址」是**平台收数据**：iotsquare 把设备的原始上行推给 WiserSquare。本章的「应用数据推送」是**平台发数据**：WiserSquare 把解析后的结构化数据再推给用户自己的服务器。两者方向相反，配置的地址也不同。

:::

推送是**应用级**配置，不是设备级配置：一个应用对应一个数据推送地址，关联到该应用的所有设备共用这个地址。

开启推送需要两步，配置由瑞兴恒方平台管理员完成，用户只需提供接收地址：

1. 为该应用填写「数据推送地址」（Push Address），例如 `https://api.example.com/gn1s067/uplink`；
2. 把设备关联到该应用，即把设备的所属应用设为该应用。

配置完成后不需要重启设备，设备下一次数据上报成功入库后即开始推送。只有同时满足下列条件的上行才会推送，否则平台会直接跳过，且不会给出错误提示：

- 设备已关联应用；
- 该应用的数据推送地址不为空；
- 本次上行属于 4.5 节列出的数据上报帧，并且已经成功写入数据库。

### 4.2 请求格式

| 项目 | 说明 |
|:---|:---|
| 请求方法 | `POST` |
| 请求地址 | 应用上配置的「数据推送地址」，**原样使用**；平台不会追加 `/uplink`、`/status` 之类的路径 |
| 请求头 | `Contenttype: application/json; charset=utf-8` |
| 请求体 | 一个 `JSON` 对象，字段见 4.4 |
| 应答处理 | 平台只读取 HTTP 状态码并记录日志，不解析应答内容；非 `2xx` 也不会重试 |

::: warning

- 请求头名称是 `Contenttype`（历史实现如此），不是标准的 `Content-Type`。接收端若要校验请求头，请按 `Contenttype` 取值；否则忽略请求头、直接按请求体解析即可。
- 推送是**异步、一次性投递**：平台不重试、不保证先后顺序，服务重启时尚未发出的推送会直接丢失。设备补发/重传的同一包数据会再次推送（平台不按 `timeUtc` 去重），请用请求体中的 `assetUniqueId` + `timeUtc` 自行做去重与排序。
- 当前版本推送**不携带鉴权信息**（没有 token 请求头）。请使用不易被猜测的数据推送地址，或在接收端按来源 IP 做访问限制。
- 接收端应尽快返回（建议 1 秒内）。平台未对单次推送设置超时，长时间不返回会一直占用连接。
- 经纬度以 `float32` 表示，经度在 113°E 附近的有效分辨率约 `1e-5` 度（约 1 米），用于牲畜定位足够，请勿据此做高精度测量。

:::

### 4.3 报文示例

**卫星定位上报（携带经纬度）：**

```json
{
  "assetName": "aabbccddeeff0011",
  "assetUniqueId": "aabbccddeeff0011",
  "battery": 87,
  "humidity": 56,
  "latitude": 22.771235,
  "longitude": 113.12346,
  "productId": "GN1S067",
  "stepCount": 1234,
  "temperature": 25.6,
  "timeUtc": "2026-10-19T08:30:00Z",
  "voltage": 3.62
}
```

**心跳 / 蓝牙上报（不携带经纬度）：**

```json
{
  "assetName": "aabbccddeeff0011",
  "assetUniqueId": "aabbccddeeff0011",
  "battery": 87,
  "humidity": 56,
  "productId": "GN1S067",
  "stepCount": 1234,
  "temperature": -3.05,
  "timeUtc": "2026-10-19T08:30:00Z",
  "voltage": 3.62
}
```

### 4.4 字段说明

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `assetUniqueId` | string | 设备 `devEUI`，16 位小写十六进制字符串 |
| `assetName` | string | 设备名称，当前固定与 `assetUniqueId` 相同 |
| `productId` | string | 产品标识，固定为 `GN1S067` |
| `timeUtc` | string | 数据采集时间，UTC，格式 `yyyy-MM-ddTHH:mm:ssZ`（秒级）；取自设备上报的时间，不是平台接收时间 |
| `temperature` | number | 温度，单位 `℃`，最多 2 位小数，可为负数 |
| `humidity` | number | 相对湿度，单位 `%RH`，整数，范围 `0`~`100` |
| `battery` | number | 电池电量百分比，整数，范围 `0`~`100` |
| `voltage` | number | 电池电压，单位 `V`，最多 2 位小数 |
| `stepCount` | number | 当天累计步数 |
| `latitude` | number | 纬度，单位度，WGS84 坐标；**仅卫星定位上报携带**，其它上报没有该字段（不是 `null`） |
| `longitude` | number | 经度，单位度，WGS84 坐标；**仅卫星定位上报携带**，其它上报没有该字段（不是 `null`） |

::: tip

推送报文与平台页面/接口查询到的数据是同一次上报的解析结果，但**不包含报警信息**（报警位、报警记录都不在推送内容里）；报警请通过 3.8 节的「警报状态历史」查看，或通过报警查询接口获取。

:::

### 4.5 触发推送的上行类型

| 设备上行 | 功能码（payload 第 2 字节） | 是否推送 |
|:---|:---|:---|
| 卫星定位上报 | `0x01` | 推送，含经纬度 |
| 心跳上报（GPS 定位失败时上报） | `0x03` | 推送，不含经纬度 |
| 蓝牙 iBeacon 上报 | `0x05` | 推送，不含经纬度 |
| 蓝牙 Eddystone 上报 | `0x06` | 推送，不含经纬度 |
| 报警上报 | `0x04` | 不推送 |
| 版本信息上报 | `0x09` | 不推送 |
| 查询 / 配置类命令应答 | `0x00`、`0xB0`、`0xB1`、`0xB2`、`0xC0`~`0xC3`、`0xD0` | 不推送 |

注：`0x02`（蓝牙定位状态上报）已废弃，若收到该帧仍会按数据上报处理并推送。

### 4.6 收不到推送时的排查顺序

1. 确认设备是否已关联应用，应用的数据推送地址是否为空；
2. 确认数据推送地址从平台服务器可以直达（平台只发起一次请求，域名解析、证书、防火墙任何一处不通都会导致失败）；
3. 确认本次上行是否属于 4.5 节中“不推送”的帧类型。

## 6 电子围栏

电子围栏用于判断绑定的设备（牲畜）是否还在指定区域内。平台把设备上报的卫星定位坐标与围栏边界做比对，一旦出现「进入围栏」或「离开围栏」的状态变化，就生成一条出圈预警，供人工排查处理。

侧边栏「电子围栏」下有两个子页面：

| 子页面 | 用途 |
|:---|:---|
| 围栏管理 | 围栏的查看、新建、编辑、删除，以及围栏与设备的绑定 |
| 出圈预警 | 进出围栏预警的查询、处理与详情查看 |

::: tip 预警是如何产生的

- 只有**卫星定位上报**携带的坐标参与判定；心跳、蓝牙等不含经纬度的上报不参与。
- 只有**状态发生变化**（围栏内 → 围栏外、围栏外 → 围栏内）才生成一条预警。设备一直待在围栏内或一直待在围栏外时，重复上报不会重复预警。
- 设备首次上报只建立初始判定基准，**不产生预警**。
- 为避免边界抖动误报，定位点与围栏边界**距离小于 1 米时该次上报直接忽略**——既不预警，也不更新判定基准。
- 状态为「禁用」的围栏不参与判定，不会产生新的预警。禁用期间设备可能已经走出围栏，**重新启用后的首次上报会与禁用前的状态比较**，因此可能立即出一条预警，属正常现象；解绑后重新绑定同理。
- 预警时间取平台收到上报的时间，不受设备时钟影响。
- 判定使用 WGS84 坐标，在地图上圈选时平台自动完成坐标系转换，用户无需关心。

:::

### 6.1 围栏管理

路径：侧边栏「电子围栏」→「围栏管理」。

页面左侧是筛选区与围栏列表，右侧地图同步回显已成形的围栏多边形（绿色区域），便于确认围栏位置是否正确。

左上角的**地图类型**是一组单选按钮：「高德地图（中国大陆）」或「谷歌地图（其他）」，按设备所在区域选择。它只决定底图与实际坐标系，**不是列表查询条件**——切换后地图与围栏回显立刻跟着变，列表本身不重新过滤。

筛选条件：

| 筛选项 | 说明 |
|:---|:---|
| 围栏名称 | 输入框，支持模糊搜索 |
| 围栏类型 | 下拉，当前只有「普通围栏」 |
| 围栏状态 | 下拉：启用 / 禁用 |

按钮说明：**搜索**按当前条件查询，**重置**清空条件，**刷新**重新拉取列表，**新建围栏**进入创建流程（见 6.2）。

列表以卡片形式展示每个围栏的名称、类型标签、状态标签和创建时间（卡片上不显示累计预警数）。卡片下方三个按钮：

| 按钮 | 作用 |
|:---|:---|
| 编辑 | 修改围栏的基本信息、边界与绑定设备，用法同 6.2。打开时会带出当前已绑定的设备，**保存时以表单里的「关联设备」为准**——把它清空即解绑全部设备 |
| 预警 | 跳转到「出圈预警」并只查看该围栏的预警记录 |
| 删除 | 删除围栏并解绑全部设备；已产生的历史预警**保留**，仍可在预警列表和详情里看到当时的围栏名称 |

::: warning

编辑与删除**只允许围栏创建者本人操作**。管理员与技术支持（FAE）账号能在列表里看到别人创建的围栏，但编辑、删除会被拒绝。围栏也只能绑定到自己名下的设备。

:::

### 6.2 新建围栏

点击「新建围栏」进入「围栏编辑」页面，整个过程分两步：先填基本信息，再在地图上画出围栏边界。

#### 6.2.1 填写基本信息

左侧表单：

| 字段 | 是否必填 | 说明 |
|:---|:---|:---|
| 围栏名称 | 必填 | 1~64 个字符，用于在列表与预警中区分围栏 |
| 围栏类型 | 必填 | 当前只有「普通围栏」 |
| 围栏状态 | 必填 | 「启用」参与出圈判定；「禁用」保留围栏但不判定 |
| 围栏描述 | 选填 | 0~255 个字符，可留空 |
| 关联设备 | 选填 | 可多选，只能从**自己名下**的设备里选。不选表示该围栏暂不绑定任何设备，此时不会产生预警 |

页面顶部有**快速定位**：分别填纬度与经度（两者之间有对调按钮，填反了可一键互换），或在右侧输入框里直接粘贴「纬度,经度」，再点「定位」，地图即跳到该坐标；点「当前位置」则定位到浏览器当前所在位置。

#### 6.2.2 在地图上绘制围栏

1. 点「开始绘制」进入绘制状态（此时「开始绘制」变灰，「完成绘制」与「清除围栏」可点）；
2. 在地图上依次点击添加顶点，**至少 3 个**，按顺时针或逆时针顺序绕一圈；
3. 点「完成绘制」**即生成并保存围栏**。顶点会自动首尾相连闭合成多边形，不需要重复点击第一个点来闭合；页面没有单独的「保存」按钮；
4. 画错了点「清除围栏」重新绘制。

编辑已有围栏时同样走这套流程，原有边界会先回显在地图上，重新绘制会整体替换旧边界。

::: tip

- 顶点数量下限是 3 个，少于 3 个构不成多边形，无法生成。
- 围栏轮廓建议留出一定余量：设备贴着边线行走时，1 米以内的定位点会被忽略，抖动容易产生反复进出。
- 围栏面积不宜过大或过小。过大时设备在围栏内移动很难触发预警，过小时误报会明显增多。
- 一台设备可以同时绑定多个围栏，各围栏独立判定、各自产生预警；若无特殊需要，建议只绑一个与放牧范围相当的围栏，便于告警归因。

:::

### 6.3 出圈预警查询

路径：侧边栏「电子围栏」→「出圈预警」。

页面顶部是筛选条件，下面是出圈预警列表。

| 筛选条件 | 说明 |
|:---|:---|
| 设备号 | 按设备 DevEUI 精确查询 |
| 围栏名称 | 下拉选择某个围栏，只看该围栏的预警 |
| 报警类型 | 「出圈」（离开围栏）/「入圈」（进入围栏） |
| 处理状态 | 未处理 / 处理中 / 已处理 / 已忽略 |
| 预警时间 | 按时间范围筛选 |

列表列：

| 列 | 说明 |
|:---|:---|
| DevEUI | 触发预警的设备 |
| 报警类型 | 「出圈」为红色、「入圈」为绿色 |
| 围栏名称 | 冗余存储的围栏名称，围栏改名或删除后仍显示当时名称 |
| 处理状态 | 未处理 / 处理中 / 已处理 / 已忽略 |
| 预警时间 | 预警发生时间 |
| 操作 | 「详情」打开预警详情（见 6.5）；「处理」打开处理弹窗（见 6.4） |

勾选左侧复选框后，可点右上角「批量处理」对多条预警一次性处理。

数据可见范围按**设备归属**划分：管理员账号可查看全部预警；普通账号只能看到自己名下设备产生的预警，也只能处理这些预警。查看不属于自己的预警详情时会提示无权限。

### 6.4 预警处理

在预警列表行尾点「处理」，或勾选多条后点「批量处理」，弹出「处理」窗口：

| 字段 | 是否必填 | 说明 |
|:---|:---|:---|
| 处理状态 | 必填 | 可选「处理中」「已处理」「已忽略」。**不能退回「未处理」** |
| 处理备注 | 选填 | 0~255 个字符，建议写明核实结果，例如「已联系牧户确认，牛群正常转场」 |

点「确认」提交。平台自动记录处理人和处理时间，无需手工填写；处理人、处理时间与备注都可以在预警详情里查看。

三种处理状态的用法：

- **处理中**：已看到预警、正在核实，先标记避免他人重复处理；
- **已处理**：预警已核实并处置完毕；
- **已忽略**：误报或无需处置（例如围栏画偏、设备临时被移出）。

已提交的预警可以再次处理改动状态（例如误标为「已忽略」后可改回「已处理」），处理时间与处理人会更新为最近一次操作；但**任何情况下都不能退回「未处理」**。

### 6.5 预警详情

在预警列表行尾点「详情」，弹出「预警详情」窗口，展示该条预警的完整信息：

| 字段 | 说明 |
|:---|:---|
| 报警记录 ID | 预警记录的唯一标识 |
| 设备号 | 触发预警的设备 DevEUI |
| 围栏 ID | 关联围栏的 ID，可用于与 6.1 列表中的围栏对应 |
| 围栏名称 | 预警发生时的围栏名称 |
| 电池电量 | 预警发生时设备的电量百分比。当前版本的出圈 / 入圈预警由服务端生成时未采集电量，该值固定为 `0%` |
| 报警类型 | 出圈 / 入圈 |
| 处理状态 | 未处理 / 处理中 / 已处理 / 已忽略 |
| 处理人 | 处理该条预警的账号；未处理时显示 `-` |
| 预警时间 | 预警发生时间 |
| 处理时间 | 完成处理的时间；未处理时显示 `-` |
| 位置 | 触发预警时的设备坐标，格式为 `纬度,经度`；点击即可弹出地图查看 |
| 警报消息 | 平台生成的描述，例如「设备离开围栏：公司右侧」 |
| 处理备注 | 处理时填写的备注；未填写或未处理时显示 `-` |

「位置」是可直接点击的，点击后立即弹出地图并标注设备当时所在位置，配合围栏边界即可判断是真出圈还是误报。
