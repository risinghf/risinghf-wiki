# WiserSquare-RHF1SFE2 使用手册

RHF1SFE2 是瑞兴恒方开发的一款消防灭火器监控终端，通过 LoRaWAN 上报灭火器的气压、温度、倾斜角度、位移和电池电量，设备本地按阈值判定越限后主动报警，适用于灭火器在位状态、压力泄漏与倾倒的远程监测。

本手册说明 RHF1SFE2 在 WiserSquare 演示平台上的使用方法，访问地址为 `https://wisersquare.risinghf.com/rhf1sfe2/`。 平台的账号登录与固件版本管理请参考
[《WiserSquare 平台使用手册》](./01.WiserSquare平台使用手册.md)。

侧边栏只有「首页」与「设备列表」两个入口，具体设备的查看、阈值设置都在「设备详情」的四个标签页里完成：

| 页面 / 标签 | 用途 |
|:---|:---|
| 首页 | 设备总数、当前报警设备数，以及全量报警历史记录 |
| 设备列表 | 设备的新增、查询、删除与休眠 |
| 详情 | 设备最近一次上报的状态快照与当前报警状态 |
| 数据 | 上行 / 下行报文的原始数据与解析结果 |
| 报警历史记录 | 该设备的历史报警逐条明细 |
| 报警阈值设置 | 各项报警阈值的查看与修改 |

::: tip 谁在做判定

阈值保存在**设备端**，越限判定也由设备完成：设备在自己的一次上报里带上「报警种类 + 报警类型」，平台只负责接收、记录与展示，本身不做阈值比较。因此平台上的阈值修改要等设备确认生效后才真正影响报警（见 3.4）。

:::

## 1 首页

首页顶部是两个统计卡片，下方是报警历史记录表。

| 卡片 / 区块 | 说明 |
|:---|:---|
| 设备总数 | 当前账号名下的设备数量 |
| 报警设备数 | 当前**仍处于报警状态**的设备数，按 DevEUI 去重。判定依据是设备最后一次上报是否带报警，设备下一次不带报警的上报到达后自动减一，因此它是实时值，不是累计报警次数 |
| 报警历史记录 | 设备产生的报警记录，按创建时间倒序，卡片右上角的刷新图标可重新拉取 |

报警历史记录的列：

| 列 | 说明 |
|:---|:---|
| DevEUI | 产生报警的设备 |
| 报警种类 | 由哪一项监测触发，以标签形式显示，如「电池电量报警」 |
| 报警类型 | 越限方式，如「低于设定的下限阈值」 |
| 创建时间 | 平台记录该条报警的时间 |
| 操作 | 「详情」查看该条报警的具体信息 |

::: warning

报警记录**不去重、不抑制**：设备每次上报只要仍带报警，就会新记一条。所以一条迟迟未处理的报警会按上报周期不断累积（下图中的电池电量报警即每小时一条）。

:::

### 2.1 添加设备

点左上角「添加设备」打开注册弹窗，按设备实际参数填写，带红色星号的是必填项。

---

![deviceCreate](https://risinghf-wiki.oss-cn-shenzhen.aliyuncs.com/upload/wisersquare/rhf1sfe2/20261027_RHF1SFE2%E8%AE%BE%E5%A4%87%E6%B3%A8%E5%86%8C.png)

---

| 字段 | 说明 |
|:---|:---|
| 设备名称 | 自定义名称，用于在设备列表和报警记录里区分设备 |
| DevEUI | LoRaWAN 设备全球唯一标识 |
| AppEUI | LoRaWAN 应用全球唯一标识 |
| 频率区域 / 子网类型 | 下拉选择设备所在的频段区域与子网类型，需与设备烧录的区域一致 |
| 协议版本 | LoRaWAN 协议版本，默认为 `1.0.2` |
| DevAddr | 设备网络地址，与 NwkSKey 一起组成网络唯一标识 |
| AppSKey | v1.0 OTAA 应用会话密钥，用于应用数据加密 |
| NwkSKey | v1.0 网络会话密钥，用于网络数据鉴权 |
| 产品类型 | 当前只有「标准 LoRaWAN」 |

DevEUI、AppEUI、DevAddr、AppSKey、NwkSKey 这几个输入框右侧带一个骰子按钮，点一下会随机生成一串十六进制值。**这是调试用的便捷入口**：注册真实设备时要填设备上标注（或入网信息里）的实际值，否则设备上报的数据进不了平台。

提交后平台会同时完成设备注册与阈值配置初始化，全部成功设备才出现在列表里；中途失败不会留下不完整的设备，重新提交即可。DevEUI 在平台内唯一，重复注册同一 DevEUI 会失败。

::: warning 前置条件

添加设备前，**当前账号需要先完成网络服务器（iotsquare）接入配置**。未配置时点「添加设备」会直接报错、无法注册，可先确认当前账号的接入信息是否已填好（见下图）。

:::

平台里可以只读查看当前账号的接入信息：窗口列出 ioTSquare 地址与开放 API Token 两项，行尾「复制」按钮可直接复制，眼睛图标用于显示或隐藏取值。

接入配置变更（例如更换服务器环境）后，原有设备需要重新注册。

### 2.2 行内操作

| 按钮 | 作用 |
|:---|:---|
| 详情 | 打开设备详情页（见第 3 章） |
| 休眠 | 向设备下发休眠命令，设备收到后进入休眠、不再按周期上报。平台不跟踪休眠状态，唤醒与恢复方式以设备手册为准 |
| 删除 | 从平台移除该设备 |

删除的影响范围需要分清楚：

- 平台侧的设备记录、阈值配置与状态记录一并删除；
- **历史报警记录与上下行报文本身不会删除**，但设备行没了，首页的报警历史里就不再显示这些旧记录；
- 设备行删除后不可恢复，重新注册需要重新填写 DevEUI 与密钥。

## 3 设备详情

从设备列表点「详情」进入设备详情页，页面顶部四个标签：**详情 / 数据 / 报警历史记录 / 报警阈值设置**，默认停在「详情」。首页报警记录行尾也有一个「详情」，用于查看那一条报警记录。

### 3.1 详情

左上方「下发异步查询」按钮会向设备下发一次查询命令，让设备把温度、气压、电量、位移、倾斜角度、版本、上报周期、关联命令列表立即上报一遍。这是**异步**的：点击后立即返回，数据要等设备下一次响应上行到达才刷新，设备离线时会一直没有变化。

左侧「设备信息」是设备最近一次上报的状态快照：

| 字段 | 说明 |
|:---|:---|
| DevEUI | 设备唯一标识，右侧「复制」按钮可复制 |
| 软件版本 | 设备上报的软件版本号，如 `1.0.7` |
| 硬件版本 | 设备上报的硬件版本号，如 `1.2` |
| 位移 | 激光测距（ToF）测得的距离，单位 `mm`，用于判断灭火器是否被移位 |
| 气压 | 灭火器压力，单位 `kPa`，用于判断是否泄漏 |
| 温度 | 环境温度，单位 `℃`，保留两位小数 |
| 供电方式 | `电池供电` / `电源供电` / `未监测` 三种之一 |
| 电池电量 | 电量百分比，仅「电池供电」时有意义 |
| 倾斜角度 | 设备当前倾角，单位 `°`，超过阈值即判为倾倒 |
| 上报周期 | 设备**当前实际生效**的周期上报间隔，单位 `s` |
| RSSI | 最近一次上行的信号强度，单位 `dBm` |
| SNR | 最近一次上行的信噪比，单位 `dB` |

这些值都来自设备上报，平台不做换算；设备从未上报过的字段显示为空或 `0`，不能据此判断故障，应先点「下发异步查询」。

右侧「当前报警状态」显示设备此刻是否在报警：正常时显示绿色对勾与「无报警」，报警时显示最后一次报警的种类与类型。它**只保留最后一条**报警，并且在下一次不带报警的上报到达后自动恢复为「无报警」——这与「报警历史记录」里的累计明细是两回事。

### 3.2 数据

「数据」标签是设备与该平台之间的报文流水，上行和下行都在这里。

| 列 | 说明 |
|:---|:---|
| DevEUI | 报文所属设备 |
| 数据 | 原始报文的十六进制字符串，如 `00 EA 08 64 00 33 D0 07 5A` |
| 命令码 | 报文的命令码名称，如 `CFRM` |
| 传输方向 | 上行为设备→平台，下行为平台→设备 |
| 推送时间 | iotsquare 把该条上行推给平台的时间。取的是网络服务器时间，**不是设备时钟**，也不是平台入库时间 |

点行首的展开箭头可以看到这帧报文解析后的 JSON，右侧「复制」按钮可整段复制。解析结果里没出现的字段会是 `null`，表示**本次上报没有携带**该数据，而不是数值为 0——例如一帧只带温度和气压的 `CFRM`，`SoftwareVer` 就是 `null`。

常见命令码：

| 命令码 | 含义 |
|:---|:---|
| `CFRM` | 周期上报，一帧里可同时带温度、气压、电量、位移、倾斜与报警 |
| `ALERT` | 单独的报警上报，只带报警种类与报警类型 |
| `QACK` | 对查询命令的响应 |
| `VER` | 版本信息上报 |
| `BAT` | 电量信息上报 |
| `DPARAM` | 设备参数上报（版本、上报周期、关联命令列表） |
| `PPAT` | 周期上报关联的命令列表 |
| `ACKOK` / `ACKERR` | 下行命令的确认，成功或失败 |

### 3.3 报警历史记录

该设备的历史报警明细，按创建时间倒序。

| 列 | 说明 |
|:---|:---|
| DevEUI | 产生报警的设备 |
| 报警种类 | 由哪一项监测触发（温度、气压、倾斜、位移、电池电量），以彩色标签显示 |
| 报警类型 | 越限的方式，以文字显示，如「低于设定的下限阈值」「缓慢超过设定阈值」 |
| 创建时间 | 平台记录该条报警的时间 |

三条使用要点：

- 一帧上报可以携带**多条**报警（例如同时超温又低电量），平台会逐条入库，因此同一时间戳下可能出现多行；
- 报警恢复**不会**删除或标记已有记录。恢复只影响首页的「报警设备数」与详情的「当前报警状态」，历史记录会一直保留，作为追溯依据；
- 排查时「报警种类」和「报警类型」要一起看：同样是「气压报警」，类型为「低于设定的下限阈值」说明是真实漏气，类型为「缓慢超过设定阈值」则说明气压是 24 小时内缓慢下降，两者的处置方式不同。

### 3.4 报警阈值设置

页面把 7 项阈值以卡片形式平铺，右上角「修改阈值」打开修改弹窗。卡片区标题为「默认阈值参数」。

| 阈值 | 单位 | 含义 |
|:---|:---|:---|
| 最小气压阈值 | `kPa` | 气压的下限。气压低于该值时设备上报气压报警 |
| 气压步长 | `kPa` | 24 小时内气压下降超过该值时，设备上报**缓慢漏气**报警 |
| 最大温度阈值 | `℃` | 温度上限，最多两位小数。温度高于该值时上报温度报警 |
| 温度步长 | `℃` | 5 秒内温度上升超过该值时，设备上报**快速升温**报警，最多两位小数 |
| 最大倾斜角度 | `°` | 倾角超过该值即判为倾倒并上报，取值范围 `0`~`182` |
| 最小距离阈值 | `mm` | 位移（测距）下限，取值范围 `0`~`2000` |
| 上报周期 | `s` | 设备的周期上报间隔，最大 `68475`（约 19 小时） |

修改弹窗里 DevEUI 为只读，其余 7 项均为数字输入框并带单位后缀；「气压步长」和「温度步长」下方各有一行说明，把上面的判定方式再解释一遍。填完点「确定」提交，点「取消」放弃。

阈值修改有四条行为需要事先知道，都与「设备才算数」这一点有关：

1. **值为 0 的项不下发**。提交时平台逐项判断，凡是非 0 的值都会下发一次命令，为 0 的项直接跳过——所以**把某项填 0 等于「这一项不改」**，不能用 0 来关闭某项报警。弹窗会把当前值预填好，正常点「确定」会把 7 项全部重下发一遍。
2. **异步生效**。命令下发后要等设备回 ACK：ACK 成功，平台才把新值从「待生效」转入正式配置；ACK 失败或超时，值会一直停在待生效状态。
3. **待生效的值在卡片上显示为橙色**。上图中「上报周期 600 s」是橙色、其余各项是黑色，而设备详情里设备当前实际周期为 181 s——橙色表示「已提交、设备还没确认」。等设备确认后颜色恢复正常，值才真正生效。
4. **改阈值不会重算历史**。已产生的报警记录保持原样，修改只影响之后的判定。

::: warning

如果修改后迟迟不生效，先确认设备在线并且能收到下行（可在「数据」标签里看有没有对应的下行记录和 `ACKOK` 上行），再看设备是否处于休眠或断电状态。

:::
