# Version History
## 4.3.5
Improved:
* Class A/B/C/R can now be switched online in real time

## 4.3.4
New:
* Can run on a gateway device, with self-activation performed on the gateway

## 4.3.2
New:
* Gateway system information now includes solar-power data, and network information now includes LTE SIM fields
* Gateway status history can be exported
* Batch export of gateway registration information
* Gateway map on the home page
* Gateway data analysis APIs: RSSI timeline for a single device, and RSSI data grouped by device
* Account expiry: administrators can set a validity period (in days) for regular users; once expired, the user's API requests are rejected
* The frequency plan can be changed when editing a gateway

Improved:
* When an application is deleted, cleanup of the related device data now runs asynchronously, so pages respond faster
* Improved device search performance
* Faster process startup and initialization

Removed:
* Subnet switching task feature

## 4.3.1
New:
* APIs for the standard relay

Removed:
* Queqiao relay

## 4.2.9
New:
* opkg upgrade packages now support gzip (tar / gzip is detected automatically, so both kinds of .ipk packages can be uploaded)
* Added the UZ927 frequency plan

Changed:
* Generic file uploads now use sha256-based filenames
* Adjusted rssi_offset in the power tables for RHF2S025B / RHF2S225 / RHF2S208C / RHF2S208D

## 4.2.8
Improved:
* Index optimization on large tables such as gateway packets, device queue, devices and device uplinks, improving query performance

## 4.2.7
Fixed:
* Fixed the power tables for RHF2S208C / RHF2S208D

## 4.2.6
* Optimized Class B initiated downlink scheduling, removing the case where GPS time was calculated too early
* Reduced resource usage and improved stability when a large number of downlinks are queued
* Added support for RHF2S208D gateways
* Fixed the log query command for RHF2S027M gateways

## 4.2.5
* Improved service stability when a large number of downlinks are queued
* Faster device details page loading

## 4.2.3
* Added support for RHF2S208C gateways

## 4.2.2
* Multicast groups can use Class R
* SIM card information is available on the gateway details page

## 4.2.1
* Class R unicast downlink

## 4.0.1
* Support for the LoRaWAN 1.0.4 specification
* Added support for RHF2S225 and RHF2S798 gateways
* Implemented the CN470 frequency plan defined in RP002-1.0.4

## 3.4
* Added version management, upgrade task management and upgrade records for deb packages
* Added version management, upgrade task management and upgrade records for bridge packages
* Removed the push-based batch bridge upgrade for gateways introduced in 3.3
* Removed the legacy per-gateway bridge / packet forwarder upgrade
* Improved the downlink command page: rssh, network sync, system information, system reboot and bridge are now integrated on one page, with downlink commands such as SSH / Serial added
* Added downlink command history
* Added moving devices between applications (3.4.6)
* Added the au915 frequency plan, with subnet types 16-23, 24-31, 32-39, 40-47, 48-55 and 56-63
* Frequency plan configuration files now support sx1302 modules (3.4.15)
* The details page now shows packet forwarder reporting status (3.4.15)
* Updated frequency plans and power tables to support RHF2S209 gateways (3.4.17)
* Added noise floor scanning and command queries for RHF2S209 gateways (3.4.17)
* Gateway online / offline status push is now available to third-party vendors (3.4.17)
* Relay device management supports AS923 (3.4.20)
* Added opkg version management and upgrade task management (3.4.21)
* Gateway details - reported information now supports the new format for network / system sensor data (gateway get_network2 / get_sensor2 commands), with more LTE fields (3.4.21)
* Gateway create / edit / query now accept map fields, supporting Google Maps and Amap; since maps are a paid service, private deployments need a third-party key to enable this feature (3.4.22)
* Multicast groups can have their pingSlotPeriod modified (3.4.22)
* Updated frequency plan configuration files to support rhf2s025b / RHF2S209 gateways (3.4.23)
* Added support for rhf2s027m gateways (3.4.24)


Improved:
- Compatibility handling for the Beacon and ClassB fields in gateway templates
- Concurrent scheduling for Class C / Class B multicast downlink HTTP APIs (3.4.9)
- Concurrent scheduling for Class C / Class B application downlink HTTP APIs (3.4.13)
- Faster iotsquare service startup: frequency plan caches are no longer preloaded (3.4.22)
- Improved the gateway details page; system information is trimmed to gateway monitoring data only (3.4.22)
- Concurrency and performance improvements (3.4.25):
    * Application-layer history records are written in batches
    * Real-time records are only pushed to subscribers
    * Second-level cache improvements for devices, applications, device sessions and gateway frequency plans
    * Binary cache instead of JSON for application and device basic information
    * Device battery and similar information is no longer updated while processing uplinks
    * The wait before processing downlinks during uplink handling is shortened where appropriate
Refactored:
* Gateway details page data is split (3.4.15)
* Device product type data migration; the device details API shows a component sidebar based on product type (3.4.15)
* Service split: each service handles its own LoRaWAN processing and API calls (3.4.16)
* Gateway push fields restructured to camelCase without abbreviations; affects the gateway heartbeat status push and the gateway online / offline push (3.4.21)
* Added unit tests for storage classes (3.4.25)
* Upgraded go-redis from v8 to v9 (3.4.25)

Bug fixes:
- Gateway frequency plan subnet switching failed (found in 3.4, fixed in 3.4.17)
- Per the LoRaWAN specification, ru864 beacon_datarategen corrected to sf9 (3.4.16)
- Gateway heartbeat status push (MQTT) now includes gateway GPS status / battery status / system load (found in 3.4, fixed in 3.4.17)
- Batch write issue in the device protocol layer and gateway layer; triggered when 100 or more packets were queued and a write was actively triggered, which dropped the newest record (found in 3.4.17, fixed in 3.4.18)
- OTAA devices failed to join in automatic subnet mode (3.4.20)
- Multicast downlink now filters out gateways that do not exist or have been deleted (3.4.22)
- Deleting a device now removes its device_activation records, so re-registering the device is no longer limited to 65535 times (3.4.22)
- Device time sync: when uplinks arrive over multiple gateway links, DeviceTimeReq uses the GPS time from the correct downlink link's RxInfo (3.4.23)
- After switching the frequency plan on the gateway details page, editing the original frequency plan failed (3.4.23)
